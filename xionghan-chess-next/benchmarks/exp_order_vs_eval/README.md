# 实验：12s 选点与 48s 参照不一致，是「评估打低分」还是「排序排掉」

- 代码：`git archive 95c2784` 干净副本（与 `benchmarks/baseline_2026-10-31-50p/` 同版本）
- 口径：`desktop_complete`、默认 `RuleOptions`、`randomness=0`、`root_limit=18`
- 脚本：`ab.py`（A 固定深度隔离 + B 静态评估隔离）。**未改任何源码**，仅在脚本内用 `dataclasses.replace` 改 `CONFIGS`，用 `_evaluate` 直接取静态分。

## A. 固定深度隔离
`depth=2/3/4` 各跑一次，`time_limit=180s`（保证不被时间截断）。**每次记录的 `completed_depth` 与请求深度完全一致（2/3/4），深度确实到位。**

## B. 静态评估隔离
取 12s 选点与 48s 参照两手，分别落子（`game.move()`），再用同一 `_evaluate` 打**行棋方视角**的静态分。

## 结论

1. **两条未命中都在固定 d3 命中参照**：`f2fc8f96` d2=`9,1-9,4` → d3=`7,12-5,12`(参照)；`502da69f` d2=`7,12-5,12` → d3=`11,3-8,3`(参照)。**归因：深度不足（12s 只到 d2），不是评估、不是排序。**
2. **排序被排除**：d3 与 12s 用的是**同一套排序**（同 `root_limit=18`、同 `_order`），却能选出参照手 → 排序没有把参照手排掉，只是 d2 的浅层估值不认它。
3. **评估只在 1 条上站错边**：`f2fc8f96` 的静态分（−15.2）反而高于参照手（−69.2），是评估把 12s 那手推上去；但 `502da69f` 完全相反（参照 54.9 > 12s −37.7），评估方向是对的。**1 条支持"评估有偏"、1 条反驳，不能据此改权重。**
4. **重要反例：加深不是解法。** 两条未命中在 d4 又都翻了——`f2fc8f96` d4=`7,0-5,0`、`502da69f` d4=`7,12-5,12`（退回 12s 的选择）。即**迭代加深在 d3→d4 之间不单调**，所以"把 12s 预算加大到能跑 d3"不能保证稳定命中参照。

## 下一步（只给一个）
**先把 hard 档做成"固定 d3"的可复现模式并测命中率/耗时**（`depth=3` + 足够 `time_limit`），而不是继续加时间预算。理由：本轮证据显示 d3 恰好是这两条的分界点，而 d4 又不稳；在"深度不单调"未查清前，加预算和调权重都是在噪声上加码。
