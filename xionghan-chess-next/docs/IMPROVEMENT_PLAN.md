# 匈汉象棋 · 对标基准与改进计划

> 本文由制作人汇编，专业章节来源标注在各节末尾。
> 基调：**不推倒重来**。所有条目都在现有令牌体系、三套棋子美术、两套渲染器之上演进。
> 排序口径见第 4 节（架构总监给出的五维打分 + 制作人的两条仲裁规则）。

## 1. 对标基准（6 个样本）

| 样本 | 最值得拿的一条 | 它解决了什么 | 本项目适用性 |
|---|---|---|---|
| **Lichess** | 棋盘即主角（明确"focus on the board"）；状态色只用于状态；背景不透明度交给用户 | 界面克制，注意力不被抢 | 高：我们信息密度已偏高，缺的是"减法"原则 |
| **Lichess Puzzle 系** | Streak（一错即止）/ Storm（限时）/ 主题筛选 | 单次训练有明确终点，难度贴水平 | 部分：纯本地可做，Glicko 题力评级需服务端→不做 |
| **Chess.com** | 每日同题 + "心" + 两步提示（先指子再指招）+ 难度按星期爬坡 | 给"每天来一次"一个理由；失误被宽容 | 高：每日一题可用**本地日期做种子**，零联网零账号 |
| **Chess.com（反例）** | 新版谜题压缩棋盘、加"轮到谁"气泡 | — | 反面清单：**不缩棋盘、不加已有信息的气泡** |
| **天天象棋** | 残局闯关的战役叙事 + 登山式关卡地图；材质统一（木纹）优先于特效 | 让"练"有进度感与目标 | 高：我们本就是匈奴/东汉题材，天然可做战役关卡 |
| **Wingspan 数字版** | 为屏幕**重新排版**而非等比还原；悬停/激活态必须明确 | 小屏可读性 | 中：侧栏信息分层可借鉴 |
| **Really Bad Chess** | 强风格不靠纹理，靠克制的色数与明确形状 | 低成本风格化 | 中：作为"少即是多"的旁证 |

**横向归纳三条**：① 头部产品都在**减少常驻信息**；② **材质统一**比加特效更能提升高级感；③ 状态反馈（选中/可走/可吃/将军）是唯一值得反复打磨的动效区。

— 游有方 · 创意总监 ／ 甄塑之 · 美术总监

## 2. 现状实测（决定优先级的三组硬事实）

**玩法侧**
- 题库 `core/data/puzzles.json` 仅 **13 条，解法全为单步**；难度 3 档（5/5/3）。
- 全仓 grep `last_move|lastMove` **0 命中** → 没有"上一步高亮"。
- `MainWindow.__init__` 直接建界面开局，**无首跑引导**；Web 反馈层只有单一 `toast()`（`web/js/app.js:82`，2.2s、无分级）。

**视觉侧**

| 项 | 实测 | 结论 |
|---|---|---|
| 主文本对比 | `--ink` on `--surface` = **16.36:1** | 远超 AA，不动 |
| 边界对比 | `--border-panel-soft` **2.77**（差 0.23 到 3:1） | 唯一踩线 |
| 无背景 × 暗色棋盘 | **推算**（未实测）：有背景图 (48,50,49) → 无背景 (73,69,59)，亮度 1.91× | **代码事实已核实**：`body[data-board-theme="dark"]` 只设 `--board-*`、无 `background-color`。**但该状态是瞬态**——`pageBackground='none'` 载入时被改写成 `'1'`，只能运行期切换触发 |
| 两套主题轴 | 绿/蓝/紫 × 系统暗色无覆盖块 | **不是缺陷**：两轴独立是设计意图（深 UI + 浅盘合法，lichess 同款） |
| 桌面棋子投影 | `board_widget.py` 全文 `shadow` **0 次**；网页有 `rgba(0,0,0,.28)` | 两端最大观感差距 |
| 落子动画 | 网页 **900ms** / 桌面 **350ms** | 桌面像"闪一下" |
| 木纹不透明度 | 网页 0.22 / 桌面 **0.12** | 桌面 classic 盘无材质 |

**工程侧**：改一个规则开关的**真实触点 = 7 处 + 3 份硬编码分组**（详见第 5 节红线表）。

## 4. 优先级排序口径

**五维加权**（架构总监制定，制作人采纳）：

`总分 = 0.30·D1 + 0.20·D2 + 0.20·D3 + 0.15·(6−D4) + 0.15·(6−D5)`

D1 用户可感知度 / D2 端数影响 / D3 杠杆 / D4 实现成本（反向）/ D5 回归风险（反向）。
档位：≥4.0 立刻做｜3.2–3.9 排入本轮｜2.5–3.1 观察｜<2.5 不做。

**制作人的两条仲裁规则**（补框架的偏置）：

1. **使能项不参与排序，直接前置。** 框架里 D1 权重 0.30，纯工程项必然低分（C-2 仅 2.60）。
   但 C-2 是"后续所有开关改动的安全网"，按分数会把它排到观察区——**这不合理**。
   故凡"让后续同类改动更安全/更省力"的项，一律作为**前置项**先行，不计分。
2. **单端高感知小改走例外通道。** 桌面棋子投影（P1-1）因 D2=2 只得 2.25，但它 ≤0.5 人日、
   可逆、且补的是两端最大观感差距。故设定：**单端 + ≤0.5 人日 + 可逆 → 直接进本轮**，不参与打分。

## 6. 明确不做（含理由，建议永久不做）

| 不做 | 理由 |
|---|---|
| 账号 / 云端段位 / 全球匹配 | 需服务端与身份体系，违背纯本地定位 |
| 任何埋点、遥测、"流失率"类指标 | 零采集是硬约束；本计划所有指标落**本机**统计 |
| Lichess 式 Glicko 题力评级 | 需服务端或复杂本地模型；用"难度档 + 星级"替代 |
| 每日推送 / 通知 | 需系统权限，与"克制、不打扰"冲突 |
| 六万级题库 | 内容成本远高于收益；先把 13 → ~40 条做深做准 |
| 缩棋盘给侧栏让位 | Chess.com 反例已验证会招致反感 |
| 桌面加 CSS 式双层外框 | 卡片语言入侵棋类；760 宽窗口要吃掉 18px 高度 |

## 7. 建议的本轮范围（制作人裁定）

**先做两个前置项，再做五项用户可感知改动**（P0-1 已降到 P2 待复现）：

1. **C-2 开关完整性守卫**（0.5 人日）——之后所有开关类改动提交即红
2. **P0-3 对比度闸门 + 边界提亮**（0.5 人日）——之后所有调色不再下探
3. **D1 上一步高亮**（3.40）
5. **P1-1 桌面棋子投影**（例外通道）
6. **B1 陪练档**（3.70）
7. **B2 默认时长 20→10**（2.70，与第 3 项同批）
8. **A1 每日一题**（3.55，依赖题库先加深 → 与 C1 同批，先扩到 ~40 条）

**理由**：前两项是"让后面所有改动更安全"的使能项；3–7 项合起来闭环三件事——
**新人有活路（B1/B2）**、**每天有理由回来（A1）**、**看得懂刚才发生了什么（D1/P0-1）**。
C1 题库加深是 A1 的前置，二者同批。

**P1 其余项**（A2/A3/C2/D2/D3/D4/C-1/C-3/P1-2/P1-4）留作下一轮；**P2 含 P2-1（暗色棋盘缺"无背景"状态）**；**P1 新增 P1-0（无背景选项被静默改写）**。
