## 1. 执行前置说明

### 1.1 为什么必须真人试玩

K5 测的是**新手上手体验曲线**：一个从未接触本产品的人，在最初几局里能否读懂局面、形成基本策略、并在第 5 局起稳定赢下入门档 AI。

这是 AI↔AI 基准（K1–K4）无法替代的：基准里双方都由程序走子，没有"读不懂档位/提示""第一局不知道该怎么下手"这类人类认知过程。把 benchmark 的得分率换算成"新手胜率"属于口径偷换，不能这么做。

因此本表的每一个结果都必须来自**真人实际落子、程序判定终局**的完整对局；组织者不得代下、不得用自测脚本补行。

### 1.2 与 K4 的边界（填表人必读）

- K4 是 **AI↔AI 的档间距**，K5 是 **新手上手体验**，两条结论**分别陈述、不得互相替代**。
- K4 当前"点估计出带、不可认证"（`contractPass=false`）——**"不可认证"不等于 K5 失败**，也不等于 K5 已有结论。它只是说那一档 AI↔AI 契约没法给出认证结论。
- 反之，即使 K5 试玩结果达标，也**不能反过来说 K4 认证通过**。
- **不得宣称「入门档已验收」**（试玩已于 2026-11-23 取消，K5 保持「未测」，无结果会产生）。本模板所有结论栏留空。

## 2. 参与人要求（3–5 人）

### 2.1 谁适合当"新手"

**适合**：
- 从未玩过匈汉象棋，也没有看过它的教学/直播/攻略；
- 最多只在试玩当天被口头告知"怎么走子、怎么算一局结束"这一层操作信息；
- 有基本棋盘类游戏经验即可（会下国际象棋/中国象棋不算污染，但需在 §2.3 备注栏标注）。

**不适合（会污染上手曲线，不得计入样本）**：
- 本项目开发者、测试者、文档作者、看过 AI_TIERS.md 或标定数据的人；
- 已经玩过本游戏任意版本的人，包括试过 demo、看过截图并研究过规则的人；
- 知道 K5 判据（35–50% / ≥55%）的人——知道目标会改变下棋策略；
- 国际象棋/中国象棋**职业或高水平选手**（其前 3 局胜率不能代表新手）。

### 2.2 局数与换人规则

- 每人**固定 5 局**，按局序号 1→5 **连续完成**，中间不插局、不跳局。
- **原则上不允许中途换人。** 若确需换人（生病、时间冲突等）：
  - 原参与人已产生的局全部标记为**无效样本**，不得保留其任何一局；
  - 新人从**第 1 局重新开始**，不得接续原人的局序号；
  - 最终有效参与人少于 **3 人**时，判定栏只能勾「样本不足」，不得给出达标/未达标结论。
- 同一人不得重复计入两次；不同设备/不同端上的同一人的对局不得合并成 10 局。

### 2.3 无效样本的判定

出现下列任一情形，该局在「有效?」栏填「否」并写明原因，且不进入 §4 的分子与分母：

1. 由非真人代下、AI 自测、脚本对局补出；
2. 中途改过规则档案、AI 难度或 AI 参数；
3. 悔棋重来后重下该局；
4. 查过"下一步该怎么走"的提示/攻略/AI 分析；
5. 局序号不连续（缺第 1–4 局，则第 5 局无效）；
6. 版本、设备或端与登记不符；
7. 终局非程序判定（人为提前结束、约定认输等）。

**注意**：剔除无效局会改变样本量。剔除后须在 §4 重新填写实际参与人数与实际局数；不足 3 人 × 完整 5 局时，只能勾「样本不足」。

## 3. 单局执行步骤

### 3.1 正向流程

1. **进入**：打开 2.2.1 客户端（桌面 / Web / Android WebView 任一，同一人固定同一端）。桌面/Web 从「人机对战」入口进入。
2. **开局设置**：
   - 规则档案：**精简**（新装默认，不要动）；
   - AI 难度：**入门（beginner）**；
   - 执子颜色：登记在案，且该参与人 5 局保持同一颜色；
   - 开局：不做特殊指定，使用程序默认。
3. **什么算"一局结束"**：由程序判定终局——将死、困毙、认输或和棋。**以屏幕出现终局结果为准**；不自行约定提前结束。
4. **局后立刻记录**（不要事后回忆补填）：
   - 参与人代号
   - 局序号（1–5）
   - 结果：**以真人参与人为准**的 胜 / 负 / 和
   - 用时（从开局到终局，单位：分钟）
   - 是否出现「读不懂档位 / 提示」的主观备注（有就写原话，没有写"无"；不要替真人归纳）
   - 有效?（是 / 否 + 原因）
5. **连续进行下一局**，重复步骤 2–4，直到该参与人完成 5 局。
