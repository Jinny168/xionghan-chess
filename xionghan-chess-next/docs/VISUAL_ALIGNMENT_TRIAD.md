# 三端视觉对齐清单（P1-8）

> 范围：桌面 `board_widget.py`（QPainter + 打包位图）、web 旧树 `web/js/app.js`（服务端权威规则的 canvas 客户端）、
> webapp 公网门面 `webapp/js/ui/board.js`（自包含 canvas）。
> 本轮**只固化现状 + 标出漂移**，不改任何视觉参数（改值属设计裁决，见第四节流程）。

## 0. 一句话结论

三套渲染器的棋子、标记、投影、动画**各自长在自己的语言里**，14 项里：
**5 项已对齐**（VA-08 上一步不透明度、VA-10 可走点 0.13 格、VA-12 落子动画 320ms、VA-13 星轨端点环按「可走点 × 0.5」派生、VA-14 特色子徽记尺寸）、**2 项近似**（VA-03、VA-09）、
**3 项形态不同不可直接比**（VA-01、VA-06、VA-07）、**4 项数值漂移**（VA-02、VA-04、VA-05、VA-11）。
VA-07（上一步方框化）已在本轮 B1 对齐；VA-14 徽记三端已落地；VA-10/VA-12 已在本轮 C2 收口；真正影响观感的剩 **VA-11（可吃点三种大小）** 一条。

## 1. 权威数据与门禁

| 位置 | 作用 |
|---|---|
| `docs/visual_alignment_ledger.json` | 清单的**权威数据**：每端一条 `lit` 代码片段 + `raw` 原值 + `scale` 归一化 |
| `tests/test_visual_alignment_triad.py` | 漂移守卫：片段必须在、数值必须对、三端分档必须与清单一致、文档必须逐条对照 |
| 本文件 | 叙述与验收方式；**清单里每一行的编号与名称都必须出现在这里**（门禁会查） |

门禁判档口径（`tolerance`）：极差 ≤ 0.005 → `aligned`；≤ 0.02 → `minor`；其余 `drift`；不可比 → `form`。
**它记的是现状快照，不是「应该相等」**：三端把同一参数对齐了，门禁同样会红，必须显式更新清单与本文档。

## 2. 对齐矩阵

单位：`cell` = 一格；`ratio` = 相对棋子盘半径 r；`ms` = 毫秒；`alpha` = 0–1 不透明度。

| 编号 | 项目 | 桌面 | web 旧树 | webapp | 档位 | 判断与动作 |
|---|---|---|---|---|---|---|
| VA-01 | 棋盘边距口径 | pad = 0.675 格（`board_geometry.py`） | pad = 0.055 × 盘短边 | pad = 0.062 × 盘宽 | form | 三种量不是同一回事：13 路上 webapp 的 pad/cell ≈ 0.85，是三者中最宽的边。想统一必须先定「按格还是按盘」。 |
| VA-02 | 棋子盘半径（格） | 0.39 | 0.39 | 0.42 | drift | webapp 盘径 0.84 格 vs 桌面 0.78 格（大 7.7%）。三端同屏对比时「公网门面的子更大」可见。 |
| VA-03 | 棋子内环半径 | 0.82 r | 0.82 r | 0.83 r | minor | 差 0.01，肉眼不可辨。记录在案，不为它改代码。 |
| VA-04 | 棋子字形字号 | 1.15 r（Bold） | 1.18 r（Bold） | 1.14 r（600） | drift | 极差 0.04 r。但三端字族不同（打包 Noto Serif SC / 系统 KaiTi / 楷体回退栈），字高比无法只靠一个数对齐。 |
| VA-05 | 投影纵向偏移 | 0.09 r | 写死 2px | 0.14 r | drift | webapp 偏移比桌面大 55%，观感更「浮」。桌面是径向渐变重心向下，webapp 是 canvas 高斯，二者不能只对数值。 |
| VA-06 | 投影实现形态 | ObjectBounding 径向渐变，外径 1.30 r，无硬边 | canvas `shadowBlur 5px` + `offsetY 2px` | canvas `shadowBlur 0.42 r` + `offsetY 0.14 r` | form | **web 旧树是缺陷态**：固定像素不随格子缩放，小盘/高 DPI 下投影比例失控。属技术债，非设计差异。 |
| VA-07 | 上一步起讫格形状 | 格内圆角方框，内缩 5%、圆角 16% | 同左（`cellFrame`），参数逐字对齐 | 格内圆角方框，内缩 5%、圆角 16%（B1 对齐） | form | 三端形态与内缩量已一致；方框四角与圆棋子不同心，两个端点都读得出来。 |
| VA-08 | 上一步标记不透明度 | 64/255 ≈ 0.251 | 0.25 | 起点 0.25 / 落点 0.30 | aligned | 三端极差 ≈0.001，已对齐；落点 0.30 稍重以区分起讫。 |
| VA-09 | 选中环半径（格） | 0.48（实心半透明盘，alpha 145） | 0.48（实心半透明盘，.55） | 0.46（描边环 + 外发光 `#c9a227`） | minor | 半径近似，形态不同：webapp 是唯一用描边环的一端。 |
| VA-10 | 可走点半径（格） | 0.13（深色主题 0.15） | 0.13 | 0.13 | aligned | 三端统一 0.13 格；深色主题 0.15 对比度补偿保留，不抹平。 |
| VA-11 | 可吃点标记半径（格） | 0.40（实心红盘，alpha 90） | 0.43（半透明红盘，.28） | 0.45（红描边环，线宽 .045 格） | drift | 形态与大小都不一致；webapp 的环与棋子边缘互相咬合。 |
| VA-12 | 落子动画时长 | 16 帧 × 20ms = 320ms | 320ms（箭头 + 扩散圆同步收口） | 320ms（移动 + 吃子扩散环） | aligned | 三端同值 320ms。 |
| VA-13 | 星轨端点环 = 可走点 × 系数 | 0.5（`STAR_HINT_RING_RATIO`） | 0.5（`cell*.13*.5`） | 0.5（`cell*0.13*0.5`） | aligned | 按比例派生：可走点改成 0.13 后，端点环字面同步跟随。 |

## 3. 验收方式（自动 / 人工）

**自动（本文件已落地）**：上表 13 项全部由 `tests/test_visual_alignment_triad.py` 逐端钉住。
任一端的字面片段或数值被单独改动 → 用例点名到文件与行；三端分档变化 → 用例报出新的分档与三端实测值。

**像素快照基线**：本轮**不做**。理由：webapp 目前没有 canvas 像素基线（`webapp/css` 的 CSS 快照与裸色棘轮已在 commit `2fabd1a` 落地，但那只管样式表，管不到 canvas 逐像素）。
新增 canvas 基线需要引入无头浏览器与稳定渲染环境（字体、DPR、抗锯齿三处都非确定），成本与收益不匹配。因此渲染结果层面**明确标「仅人工验收」**，见下表。

| # | 人工验收项 | 怎么验 | 通过判据 |
|---|---|---|---|
| M-1 | 字形与字重 | 三端各开一局，同一局面截图并排 | 同一枚子的字高/盘径肉眼一致；无「网页字幕感」或「桌面过粗」 |
| M-2 | 投影柔边 | 浅色 `classic` 主题，放大到 200% 观察棋子下缘 | 投影重心向下、无硬边、不与棋子脱开（VA-05 的 0.55 倍差应能看出） |
| M-3 | 盘底色与纸纹 | 四主题各看一次 | 无明显「塑料平涂」；暗角不压四角刻线（webapp `drawBoardSurface` 的暗角口径） |
| M-4 | 深色主题标记对比 | `ink` / `dark` 主题下摆一个可走点和一个可吃点 | 可走点不消失、可吃点不与红叉混淆（桌面为深色单独放大到 0.15 的理由） |
| M-5 | 高 DPI / 小盘缩放 | 浏览器缩放 50% 与 200%，或窗口拉窄到最小宽度 | 线宽不发虚、投影比例不失控（专抓 VA-06 的固定 px 缺陷） |
| M-6 | 落子手感 | 同一手棋在三端各走一次 | 动画结束时无回弹、无残影；460ms 与 190ms 的差异能被感知但不突兀 |
| M-7 | 状态叠加层级 | 将军 + 选择 + 可走点 + 上一步四态同屏 | 层级仍是「上一步 < 可吃 < 选择 < 将军」，都亮等于都没亮视为不通过 |

## 4. 改值流程（怎么在不破坏门禁的前提下对齐）

1. 先在本文档与 `docs/visual_alignment_ledger.json` 同时写下**目标值与理由**（三端各自的新 `lit`/`raw`），让评审看到「这是有意统一」；
2. 改代码，跑 `pytest tests/test_visual_alignment_triad.py`：红是预期的（快照未更新）→ 按新值更新清单；
3. 三端必须**同一 commit**改完；只改一端会被本办法档位判定直接判成新的 `drift`；
4. 涉及 `webapp/css` 或 `webapp/js/ui/board.js` 的改动，按既有纪律重建 bundle（S1 `--check` → S3 bundle → S5 fixtures），否则线上仍是旧引擎/旧样式；
5. 规则语义零改动 ⇒ `RULE_VERSION` 不升。

## 5. 与既有项的关系

- **P2-10（`webapp/css` 门禁）**：已在 `2fabd1a` 落地（快照 + 裸色扫描白名单 106→139）。本清单补的是**canvas 层**，两者不重叠：CSS 快照管不到画在 canvas 里的棋子与标记。
- **E-1（三渲染器）**：本条即 E-1 的落地物证；`web/` 与 `webapp/` 两棵 app.js 仍不同源，任何「只改网页」的改动必须先问清是哪棵树。
- **P1-6（特色棋子视觉编码）**：形状徽记（VA-14）已三端落地——web 旧树、webapp、桌面（glyph/位图/回退三路径）同参数；落地流程为先改清单再改绘制，否则门禁会把「新编码」当成漂移拦下。
