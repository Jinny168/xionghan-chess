## 1. 验收基线（判定时直接引用，不再逐条重复）

### 1.1 资产

| 项 | 基线值 | 可核方式 |
|---|---|---|
| 资源目录 | `web/assets/pieces/{traditional,modern,cartoon}/` | `ls web/assets/pieces` |
| 张数 | 每风格 22 张 = 11 型 × 2 色；三风格共 **66** 张 | `ls web/assets/pieces/<style> \| wc -l` |
| 覆盖的 11 型 | 漢/俥/傌/相/仕/炮/兵/尉/射/檑/巡（黑：汗/車/馬/象/士/砲/卒/衛/䠶/礌/廵） | 文件名后缀 `han/che/ma/xiang/shi/pao/bing/wei/she/lei/xun` |
| **缺图 3 型** | **甲（armor）/ 刺（assassin）/ 楯（shield）**，黑方 胄/伺/碷；3 型 × 2 色 × 3 风格 = **18 张缺失**，必须回退字形 | 目录内无对应文件 |
| 画布 | 160 × 160，RGBA（带透明通道） | 图片属性 |
| 圆盘在画布内的占比（**源盘径，仅供断言用**） | traditional / cartoon **0.856** → 源盘径 **137 px**；modern **0.9188** → 源盘径 **147 px** | 量 PNG 内圆盘外径 |
| 目录字节数（预算基数） | 三风格字节数求和 = **355,621 B（347.3 KB）**，判据 ≤ 512 KB | `find web/assets/pieces -name '*.png' -printf '%s\n' \| awk '{s+=$1} END {print s}'` |
| **环厚占盘径比（三风格不同，设计差异）** | traditional **2.19%** · modern **3.40%** · cartoon **5.84%**；按 110 px 盘径折算 ≈ **2.4 / 3.7 / 6.4 px** | 量外环描边宽度 ÷ 盘径 |
| 字形来源 | 位图内的字形为**楷体系**（与系统楷体墨色 IoU 0.70–0.76）；旧兜底 `Noto Serif SC` 仅 0.31–0.36。**楷体兜底本轮不做**，故只作观测项（C-4） | 见 C-4 |

> **口径保护**：三风格环厚本就不同（卡通环明显更粗），**不得**按「三风格环厚应一致」判缺陷，见 D-5。

### 1.2 几何不变量

| 项 | 基线值 | 出处 / 关系 |
|---|---|---|
| cell | `cell = min(W_board − 26, H_board − 26) / 13.35`（**W/H 指棋盘控件自身，已扣除右侧面板**；16:9 下高度先卡死） | `src/xionghan_chess/desktop/ui/board_geometry.py:29-31` |
| cell 实测锚点 | 760×560 → **31.54**；1260×850 → **53.26**；1920×1080 → **70.49** | 美术实测，**不要用窗口尺寸硬推** |
| 盘径 | **0.78 × cell**（半径 0.39 × cell），**三风格一致**，与字形模式**完全相同** | `board_widget.py:333` `radius = min(cw,ch)*.39` |
| 绘制路径（**几何定稿：裁 bbox**） | 按 `PIECE_BBOX` 裁剪 → 缩放到 `dev` → **1:1 blit**（不再按「画布 = 盘径 ÷ 风格占比」算） | bbox 见下 |
| `PIECE_BBOX` | traditional / cartoon **(12,12,137,137)**、modern **(7,7,147,147)** | 裁后即源盘径（137 / 147 px） |
| `dev` | `dev = 0.78 × cell × DPR` | 清晰度就判 `dev / 源盘径`（见 D-4） |

> **⚠ 已作废的旧公式**：「画布边长 = 0.9112/0.8489 × cell」**不再参与绘制**，风格占比只留作断言（0.856 / 0.9188）。**验收请按 bbox → dev 量，不要按不存在的画布公式量。**

| 项 | 基线值 |

## 5. 几何（D）

> 量法统一：100% DPI、窗口 1260×850（cell=53.26）、`desktop_complete`。截图后量**同一格棋子的圆盘外径与圆心**，每档 3 次取均值。

| 用例ID | 前置条件 | 操作步骤 | 判定标准 | 结果 | 观察记录 |
|---|---|---|---|---|---|
| D-1 | 对局中，取一个位图子（如 (4,4) 的 俥） | 三档风格各截一张（同窗口同尺寸） | 该子**圆心像素坐标**三档两两相比，位移 **≤ 1 逻辑 px**；超出即不通过（位图与字形居中锚点不一致） | | |
| D-2 | 同上 | 量该子圆盘外径 d（px），并用相邻两条棋盘线间距量 cell | ① **d / cell = 0.78 ± 1%**（0.772–0.788）—— 这才是「棋子有没有被意外缩小」的真判据，任何窗口都成立；② 实测 d ≥ 理论值 `0.78 × cell × DPR` 的 **95%**；③ 三档 \|d − d₀\| / d₀ ≤ 2%；④ 三档 cell 相同（±0.5 px），且与 §1.2 锚点（53.26）差 ≤ 2% | | |
| D-3 | **4K 面板 @200%**（逻辑 1920×1080），F11 全屏 | 截全屏图，量任一位图子的圆盘外径（**物理**像素） | **≥ 108 物理 px**（该场景 dev≈110）。**无 4K 环境时标「未测」，不判失败**；1080p 原生面板开 200%（逻辑 960×540）不适用本阈值，改用 D-2 相对判据 | | |
| D-4 | 1080p@100%、4K@200%、5K@200%、6K@300%（有则测，无则记「未测」） | 每档算 `dev = 0.78 × cell × DPR`，再算 `dev / 源盘径`（traditional/cartoon **137**、modern **147**），并看棋子边缘锐度 | ① **按风格分别判**（现代源盘径最大、最耐放大，**不得三风格同一门槛**）：`≤ 1.0` 达标；`1.0–1.1` 可接受（记录，不判失败）；`> 1.15` 记为**已知缺陷**；② 主理人实测锚点：1080p / 4K@200% → **0.80× / 0.75×**；5K@200% → 传统/卡通 **1.11×**、现代 **1.03×**；6K@300% → **1.20× / 1.12×**（执行时按本机实测复核）；③ 记录每档的 cell、DPR、dev、比值 | | |

## 6. 性能（E）

> 统一 offscreen 复跑，取 **60 帧均值**，同时记 p100；同机连跑 2 次取较差的一次。片段存临时文件（如 `%TEMP%/perf_atlas.py`，**不入库**）。

```bash
cd <repo>/xionghan-chess-next
QT_QPA_PLATFORM=offscreen python %TEMP%/perf_atlas.py 840 traditional
QT_QPA_PLATFORM=offscreen python %TEMP%/perf_atlas.py 1470 modern
QT_QPA_PLATFORM=offscreen QT_SCALE_FACTOR=2 python %TEMP%/perf_atlas.py 1470 modern
```

```python
# perf_atlas.py —— 只读复用现有 API，不改源码
import sys, time
sys.path.insert(0, "src")
from PySide6.QtWidgets import QApplication
from PySide6.QtGui import QPixmap
from xionghan_chess.core.game import Game
from xionghan_chess.core.profiles import PROFILES
from xionghan_chess.core.model import Color
from xionghan_chess.desktop.ui.board_widget import BoardWidget

size = int(sys.argv[1]); style = sys.argv[2]
app = QApplication([])
board = BoardWidget()
board.set_game(Game(PROFILES["desktop_complete"]), Color.RED)
board.set_appearance("classic", "none", style)
board.resize(size, size); board.show()
pm = QPixmap(round(size * board.devicePixelRatioF()), round(size * board.devicePixelRatioF()))
board.render(pm)                       # 预热
t = time.perf_counter()
for _ in range(60):
    board.render(pm)
print(f"{size}px {style}: {(time.perf_counter()-t)/60*1000:.2f} ms/frame")
```

## 10. 口径变更记录（供复核，不是用例）

### T-1〔已裁定〕D-3 拆成「通用相对判据 + 单列 4K」

原「200% DPI 下盘径 ≥108 物理 px」是拿 4K 的数当通用门槛（1080p@200% 实际只有 54.4 物理 px），已拆为两条：

| 拆分 | 判据 | 落点 |
|---|---|---|
| **D-3a（通用）** | `盘径 / cell = 0.78 ± 1%`，且实测盘径 ≥ 理论值 `0.78 × cell × DPR` 的 **95%** —— 这才是「棋子有没有被意外缩小」的真判据，任何窗口都成立 | **D-2** |
| **D-3b（单列）** | **4K 屏 @200%** 下盘径 ≥ **108 物理 px**（该场景 dev≈110）；无 4K 环境标「未测」，**不判失败** | **D-3** |

### 三处口径已作废（不要按旧口径写/量）

1. **「画布 = 0.9112 / 0.8489 × cell」作废**：几何定稿改为裁 bbox（`PIECE_BBOX`）→ `dev = 0.78×cell×DPR` → 1:1 blit，风格占比退出绘制路径，只留作断言。见 §1.2。
2. **「字高 / 盘径 ∈ [0.50, 0.55]」作废**：该目标本身拍错（逐字天然 0.394–0.533，相/士/巡 会全判不合格），且楷体兜底本轮不做。**本清单内不含此条，也不要新增。**
3. **`du -sk` 不作预算依据**：它报的是簇对齐磁盘占用（480 KB），进包按字节是 355,621 B。H-1 改用字节求和。

### 口径保护（写在这里防被当成缺陷）

1. **三风格环厚不同**（2.19% / 3.40% / 5.84%）是设计差异 → D-5 只判「连续、无锯齿」。
2. **缺图回退的底色必须同风格**（象牙白面 + 该风格环色），不是旧金色系 → C-1⑤；笔锋（楷 vs 宋）只作观测项（楷体兜底本轮不做，见 C-4②）。
3. **默认 glyph 必须与 1.7.0 逐像素一致**，这是「老用户界面不许突变」的硬要求 → B-4 / B-6。
4. **图谱缩略图必须固定走 image 路径**，不随棋盘 `piece_render` 变化；glyph 模式下图谱里出现金色圆片即为缺陷 → A-6。
5. `DESIGN_PIECE_MARKERS.md` 的「识别标记」本轮不实施，**不得**据此判不通过。

### 已知问题（记录，不判失败）
