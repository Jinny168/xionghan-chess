## 二、实测结论（可直接引用）

### 1. 高级档确实能在多数局面多走一层
- 判据：**21 次里 ≥18 次完成 depth 2**；
- 本仓实测 **18/21（阈值 18/21，恰好达标、无余量）**，唯一不稳局面是 D2（1/3 轮）；
- 另一套局面集测得 19/21（指纹不同，仅作旁证）；
- 按完成时刻计的余量：min 58.8% / p50 67.9%。

### 2. EBF（有效分支因子）≈ 3.9，深度是“指数账单”
16 个确定性局面（`bench_roots` 生成，seed 与 plies 均生效）：

| 指标 | 值 |
|---|---|
| `EBF(3/2)` | **p50 = 3.89**，p90 = 6.04，max = 6.15 |
| `EBF(2/1)` | p50 = 13.57（被“d1 极便宜”放大，**不可用于增速估算**） |
| 90s 内完成 d3 | 15/16 |

→ **多买一层需要约 4 倍提速**；常数优化的现实区间是 1.3 倍量级，因此**不投“提速换深度”**。

### 3. 12 秒预算下的真实分布
同一批 16 局面，hard / `root_limit=18` / `randomness=0`：

| depth | 局面数 |
|---|---|
| d1 | 3 |
| d2 | 10 |
| d3 | 3 |

到 d2 的局面，`t_d2` 中位约 **6.0 秒** → 12 秒里约 **6 秒是白等**。

### 4. 排序已经很好，不该先动
6 局面 × 93 次 cut：**88 次（94.6%）发生在 index 0**（第一个孩子）。
→ killer/history 改善的正是“第 1 位不是最优”，而这种情况只剩约 5%，**预估收益 <5%**。

> 注意：不能看“cut 率”。实测 cut 率只有 7.5%–28.6%，但那反映的是**cut 机会少**（全窗口节点 `beta=+∞` 永不 cut、`branch_limit` 截断的孩子根本不进循环），不是排序差。

### 5. 评估是可动杠杆，但当前没有位置表（PST）
- 现有 `_evaluate` 共 10 项：材料 / 中心距离 / 兵推进 / 出子 / 王位置（中局、残局）/ 池价值 / 攻击压力 / 机动性 / 王安全 / 将军奖惩；
- 单次评估 **3410 µs**，占单节点 **7.2%**；其中 `in_check` 占评估 22%（每次评估调两次）；
- 三个候选结构项成本极低（开放线 7.5 µs、深入兵 2.2 µs、车炮同线 3.5 µs，合计 ~0.4%）；
- **关键**：用 w=12/15/18 测“是否改变选点”得到 0/3，但权重扫描显示**阈值约 w=30（¼ 个兵值）**，w=30 即改变 1/3 局面的选点。→ “改评估不改变选点”是**权重太小造成的假象**。

## 三、已否决方案（附理由，避免重试）

| 方案 | 结论 | 理由 |
|---|---|---|
| 提速换深度 | **否决** | EBF(3/2) p50=3.89 → 需 ~4× 提速 |
| 提前返回（k 阈值跳过下一层） | **否决** | 34 个“12s 内本来能到 d3”的局面上，k=3 误拦 1 个（预测 9.09s vs 剩余 8.80s，实际 7.98s 能完成，超 3.3%）；k=2 零误拦但仅省 2.17s/局且在该子集触发 0 次；k=4 误拦 5/34 |
| killer/history 排序 | **暂缓** | cut 94.6% 落在 index 0，收益 <5% |
| 中级档预算 5s→6s | **回退** | 预算为“软上限”（`_guard` 逐子节点检查，根着法可越界 0.1–0.5s），加秒只是挪结算点；且 6s 在边界局面上两台机器结论相反 |

> 提前返回否决的根因不是“k 没调好”，而是**用单次耗时比值预测下一层，在 EBF≈3.9 且方差大时，判据的分辨率（0.6%–3.3%）低于系统噪声**。

## 四、本版本没解决的两件事（如实写）

1. **“每手等满 12 秒”未解决**：能消除白等的只有“让下一层在预算内跑完”（需 4× 提速，已否）或“按层硬配额”（规则，会切掉本可完成的层）。预测式提前返回已证伪。
2. **高级档只在多数局面多一层**：本仓 18/21（恰好达标、无余量），极密集局面（38 子/45 着）在 `root_limit` 32 与 18 下均为 depth 0。

## 五、测量纪律（本轮用返工换的）

1. **局面必须确定性生成**：用 `bench_roots.build_position` 的 median-move 策略（同 seed 逐字段一致）；**不要用“seed/plies 自对弈”**——`choose_move` 是时间受限的，同一 seed 换机器/负载会走不同的棋（同名 L6 曾出现 62/129、62/85、62/105 三种指纹）；
2. **同批同跑**：基线会漂（同代码 `t_d2` 跨轮差 ±0.4s ≈ 8% 预算），分层判据不可跨批复用；
3. **`nodes` 只验基线**：同 depth 偏差 >15% 判环境不合格；跨 depth 的差异是“少算一层”的合法结果；
4. **不改写历史**：提交信息里的旧口径以正文为准，不 amend、不 squash；
5. **夹具不覆盖**：换代存新名，否则引用它的历史数字全部作废；
6. **不等式推出的数只能以不等式出现**（`≥x`/`≤x`），不得转写成区间或点值；要区间必须实测。

补两条本轮的“指标陷阱”：
- 判断“某优化有没有空间”，先确认**指标测的是优化对象**，而不是它的副产品（cut 率 ≠ 排序质量）；
- **“贴近真值”的预测不一定更安全**——k=4 比 k=3 更贴近 EBF 真值，恰恰是它误拦。

## 六、下一轮建议

| 优先级 | 事项 | 依据 |
|---|---|---|
| P1 | **结构评估项**：开放线 / 深入兵 / 车炮同线，权重从 **30** 起 | 成本 ~0.4% 评估耗时；w≥30 能改变选点 |
| P2 | `in_check` 在评估内缓存 | 占评估 22%，顺带 `_search` 可复用 |
| P3 | 完整 PST（分棋子位置表） | 当前位置项只有“到中心距离”，车/炮/马/巡不知自己在哪条线 |
| P4 | 硬配额（D9，按层分配时间） | 唯一不依赖预测的“吃白等”方案 |
| P0（服务端） | D6：AI 搜索并发上限 | 多房间并发时所有房间 AI 同时降一层；且与登录 PBKDF2 共用线程池 |

验证口径（评估改动）：`t_d2` 前后对比 + “与深预算选点一致率”，**不要只看单局面选点**（medium `randomness=0.05` 会污染）。
