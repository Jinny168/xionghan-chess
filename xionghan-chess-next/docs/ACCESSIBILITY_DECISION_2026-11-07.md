# 棋子级无障碍：决策记录（2026-11-07）

> 结论先行：**只做 C（快照朗读 + 键盘闭环），A/B 永久不做；C 单独实现，不拆成"只朗读"的半截。**
> 本文件是决策依据，不是实施计划。实施前请重读「三、实施前必须确认」。

## 一、事实（实测，勿再重复验证）

- 桌面 `BoardWidget` 是**单个自绘 `QWidget`**：`QAccessible.queryAccessibleInterface(win)`
  下 `role=Client, name='', description='', childCount=0`。
- 也就是说：**棋子、坐标、走法在读屏里结构上不存在**，不是"读得不好"，是"没有"。
- 棋盘上唯一的无障碍节点是棋盘自己（无名）。
- 现有无障碍只到按钮层：`setVisible(False)` 的子控件**仍在树里**，被标
  `state.invisible=True`，读屏据此跳过。

## 二、三条路径与结论（来源：柯桥良 · 技术架构总监）

| 路径 | 代价 | 判定 |
|---|---|---|
| A 自定义 `QAccessibleInterface`（90 个虚拟节点） | 语义模型 + 每步 `updateAccessibility` 事件同步；rect 要高 DPI 映射；维护中高 | **永久不做**（除非触发条件成立，见下） |
| B 叠 90 个透明子控件 | 每帧 90 次 `setGeometry`、Tab 顺序被切成 90 段、焦点抢夺 | **不做**（代价大于收益） |
| **C 快照朗读（快捷键 + 文本生成）** | 1 个快捷键 + 1 个纯函数，控件树零改动，风险近零 | **做** |

技术上不是野路子：Qt 官方推荐就是实现 `QAccessibleInterface`（通常继承
`QAccessibleWidget`，`QAccessible::installFactory()` 注册、`updateAccessibility()` 通知）。
未核实的点：`QAccessible::Role` 的具体枚举取值，落地前要核。

**回头做 A 的触发条件（三条同时成立）**：① 出现视障用户反馈或发行方/资助方明确要求；
② 棋子语义与规则收敛、不再频繁改；③ 有人能实测 NVDA/VoiceOver。

## 三、产品判断（来源：游有方 · 创意总监）

**做，但只做 C + 键盘输入层。** 依据不是受众规模，而是"结构上不可及"：读屏拿到空树是
**缺失**，不是体验差；而象棋有盲棋传统与标准记谱法，语音界面是玩家已有的心智模型，
迁移成本全品类最低。

**最小闭环（缺一条都算半截）**：
- 快捷键朗读**分块**快照（按方/按兵种），默认只播**差量**记谱（"红炮二平五"），
  禁止每步重读全盘；
- 方向键移动光标、回车选子、回车落子；
- 全键盘可完成，鼠标非必需。

**实施前必须确认**：
1. **不要只做"朗读快照"就交付**——只朗读不能选子落子，是"能听不能玩"，对项目是负分。
2. **降级线**：若键盘闭环在 3 人日内跑不通，降级为"仅观棋朗读"，并在路线图写死
   "读屏仅支持观棋"，此后不再重提。
3. 落地后发布说明可用这句话：**"支持全键盘操作与读屏朗读，视障玩家可独立完成整局对弈。"**
   在键盘闭环做完之前，**不得**使用这句或类似表述。

## 四、验收判据（将来实施时用，可核对）

1. `queryAccessibleInterface(BoardWidget)` 的 `role` 为表格/网格类，`childCount ≥ 90`（含空格）。
2. 读屏能报出"e4 有红车"这类"坐标 + 棋子/空"。
3. 方向键可逐格移动读屏焦点，每格都播报坐标与内容。
4. 纯键盘完成一次吃子，200ms 内听到结果播报（验证事件而非轮询）。
5. 无回归：同场景 draw 耗时与改动前差 < 5%，Tab 顺序不进棋盘每格。

> 注：判据 1–3 属 A 路径的能力。若最终只做 C + 键盘（不含 A），验收应改为
> "键盘可完成整局 + 每步有差量播报"，并**明确声明读屏不支持逐子导航**。

## 五、本轮不做的理由（挡下轮重提）

不是"本期不做"，是**顺序问题**：C 的键盘闭环是 3–5 人日的交互改造（光标状态机 +
选子语义 + 与现有快捷键的冲突排查），不是"顺手加个快捷键"。把它塞进一次以清债为目标的
收尾轮，结果一定是"朗读做了、闭环没做"，正好踩中上面第 1 条禁止项。
