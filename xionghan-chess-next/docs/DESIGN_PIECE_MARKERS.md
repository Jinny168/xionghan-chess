## 0. 背景：为什么曾经考虑过

甲（armor）、刺（assassin）、楯（shield）三种棋子的机制都是**反直觉**的：

- 甲：走完才结算，成线判定是**全盘扫描**，不是只看本次走出的那条线；
- 刺：与「起点关于落点的镜像格」上的敌子反向兑子，双方同时移除；
- 楯：自身不可被吃，并保护相邻友子。

玩家看错这三子的代价是**直接输棋**，而看错俥/炮/傌通常只是吃亏。因此从「学得会」角度，它们比传统子更值得被视觉区分。

但这**不足以**论证要补 18 张位图（3 子 × 2 色 × 3 风格）。更便宜的中间解是「不改资源、只在绘制层加一个稳定的识别标记」——本文记录该解必须满足的约束。

适用范围：这三子只在 `desktop_complete` 出场，每盘 **12 / 62 枚**（19.4%）；其余档案为 0。

## 2. 关键依据：动画扩散环在 1.2R 处与标记**同心同半径**（「缺口环」因此划掉）

动画环公式（`board_widget.py:306-310`）：

- 半径 `= 格 × (0.25 + progress × 0.38)`
- 笔宽 `= max(1.0, 5.0 × (1 − progress))`
- `progress = min(1, frame / 14)`（`:292`），定时器 25 ms/帧（`:58`）→ 全程 **350 ms**

**恒等式**：`1.2R = 1.2 × 0.39 = 0.468 格`；解 `0.25 + 0.38p = 0.468` 得 **p = 0.5737**。
即：动画环**必定**在 p≈0.574 穿过 1.2R，**这一结论与窗口尺寸无关**（两边同为「格」的倍数），放大窗口不会避开。

420×420 实测（`usable = 420 − 26 = 394`；`格 = 394 / (12 + 1.35) = 29.51`）：

| 量 | 值 |
|---|---|
| `R = 0.39 × 格` | **11.51 px** |
| 标记拟设半径 `1.2R` | **13.81 px** |
| 动画环在 p = 0.574 的半径 | **13.82 px** |
| 该帧动画环笔宽 `5 × 0.426` | **2.13 px**（与标记 2 px 描边差 **0.13 px**） |
| 交会时刻 | 约第 8 帧，**t ≈ 200 ms** |

**结论：同心、同半径、笔宽几乎相同、且是红/绿高对比——每走一手，标记会短暂「变成另一个环」。**
→ **大缺口环（270° 以上）方案划掉**：它在 350 ms 动画窗口内无法与扩散环区分。

## 3. 判据（两条）+ 建议形态

判据从「不能是圆」精确化为：

1. **不能是填充体**（盘/点）→ 会被读成落点 / 选中 / 将军；
2. **不能是闭合细环**（含大缺口环）→ 会被读成动画扩散环。

**建议形态**：**3 个固定角位各画一段约 20° 的弧，用「亮几段」区分三子**（甲 = 1 段、刺 = 2 段、楯 = 3 段）。

理由：非填充、非闭合；段数天然可数，不依赖颜色（色弱可辨）；在 2 px 线宽下仍可数（见第 4 节最小尺寸）。

## 4. 位置：用**钳位公式**，不是写死 1.2R

`R = 0.39 × 格`（`:333`）：`格` 由 `board_geometry.py:29-31`（`_OUTER_RATIO = 1.35`、`_PAD_RATIO = 0.675`）算出，`可用区 = rect().adjusted(13,13,-13,-13)`（`:167`）。

```
环半径 = min(1.2R, 0.5 × 格 − 描边宽)
```

**为什么必须钳位**（420×420 实测）：

| 方案 | 单边余量（到邻子环） | 判定 |
|---|---|---|
| 1.2R + 2.0 px 描边 | `14.76 − 13.81 − 1.0 = −0.05` → 余 **0.94 px** | **越界 0.11 px**，顶到邻子的环 |
| 1.15R + 1.5 px 描边 | **1.52 px** | 可行 |

（`半格距 = 格 / 2 = 14.76 px`；1.15R = 13.24 px。）

**盘内不可用**（两条原因，别省）：

- 字形占满盘面——字号 ≈ `1.15R`，`drawText` 在 `2R × 2R` 框内居中（`:350-352`）；
- `piece_style == "modern"` 时在 **0.82R** 另有一圈 1 px 装饰环（`:347-349`），任何**内环**标记都只在三种风格中的一种里撞形，是最难排查的缺陷。

**边线上的子**（`desktop_complete` 的 row0 有射/楯/甲/刺/檑 五枚贴边）：
到外框 `pad − 1.2R = 19.92 − 13.81 = 6.11 px`，但外框是 `QPen(theme["frame"], 5)`（`:140`）**向内占 2.5 px** → 实剩 **3.61 px**。不裁切，但很挤。

**对比度**：外环描边对比度取决于**棋盘底色**而非棋子色，须逐一验证 5 套主题，尤其 `dark`（棋盘 `#34302b`）。

**与起点角标的擦边**：角标尖端在对角 `(0.14 + 0.2) × √2 = 0.481 格`，外环 `0.468 格` → 环从尖端内侧擦过（差 `0.013 格 ≈ 0.38 px`），视觉上像「环上挂了 4 个刻度」。角标落位是 **rows 4 / 8 × 偶数列（0,2,…,12）**，外加 **(3,1)(3,11)(9,1)(9,11)** 四点（`:220-222`）——不是「row 3/9 的偶数列」。甲/刺/楯 开局在 row0/row12 不落角标位，但走到上述点位会叠（见验收 3）。

## 5. 三条验收

1. **两两可分辨**：420×420 窗口截图，三种标记必须**靠形态**分辨（不接受「放大才看得清」，不接受只靠颜色）。
2. **动画中不被误读**：走一手棋，在动画 **t ≈ 200 ms**（p≈0.57）那一帧截图，标记不得被读成扩散环。
3. **与角标不糊**：把甲走到 `(4,0)`（起点角标位）截图，外环与角标不得合成一个「新符号」。
