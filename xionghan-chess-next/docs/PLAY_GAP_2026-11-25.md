## 四、明确不做的清单及理由

以下不是"暂时搁置"，是本项目判定**不该做**的结论；每条理由自己成立，不只写"不做"。

| 不做 | 为什么（自己长出来的结论） |
|---|---|
| AI 实时自然语言着法讲解／"下一步思路"生成 | 三条硬伤：① 复盘口径已定为「浅层参考、非权威、不显示精确分值」（`CHANGELOG_2.2.1.md`），实时讲解会诱导"AI 权威"心智，与已发布承诺相反；② 本地模板质量有限（`ITERATION_PLAN_ROUND_NEXT.md:246` P2-2 已降级）；③ 离线端 movegen 瓶颈，无法承诺全端同深度（`ITERATION_PLAN_ROUND_NEXT.md:182`）。**替代路径是 C1 的内容型解析**——同样解决"为什么"，但不撒谎、不联网、不重算。 |
| 题力自适应／Glicko／服务端题力评级 | 需服务端与账号，直接违背硬约束；且 `core/daily.py:5-6` 明确「每日一题不做自适应，所有人同一题才谈得上约定」——自适应会破坏跨设备一致性。用"难度档 + 星级 + 本机错题"本地替代即可。 |
| 外部强引擎（Pikafish/NNUE/CCZero 接入） | 标准引擎不识别 13×13 + 自定义兵种；权重成对替换与版本耦合；零联网约束；调度已裁定不做，重开条件见 `ITERATION_PLAN_ROUND_NEXT.md:184`。且 Pikafish 已移除限棋选项，不能拿来当难度阶梯——本项目深度阶梯已锁定且标定完成，没有引入理由。 |
| 题库规模化到 6 万／620 关 | 成本失衡；48 条已超早期目标，质量（消除虚假唯一解、手数规范化）比数量更重要（`CHANGELOG_2.2.0.md §题库`）。 |
| 多计时档位 | 改状态机＋存档＋多端 UI＋服务，成本真实；默认时长调整已解决节奏诉求；调度与计划双票不做（`ITERATION_PLAN_ROUND_NEXT.md:35` A2、`:247`）。 |
| PGN/FEN 互通／棋谱扫描／打谱 | 标准 FEN 表达不了 13×13 + 自定义兵种；格式改动触发三版本号联动（`ITERATION_PLAN_ROUND_NEXT.md:36,246`）；拍照识别偏离核心、面窄成本高。 |
| 揭棋／翻翻棋变体 | 需信息不对称规则 + AI 可见性模型，成本最高（`ITERATION_PLAN_ROUND_NEXT.md:252`）；调度本轮裁定不做。 |
| 在线对弈／棋社／联赛／段位／弹幕／皮肤付费 | 零联网／零账号／零采集硬约束，全盘排除（`ITERATION_PLAN_ROUND_NEXT.md:262`）。 |
| 全屏庆祝层／BGM／高特效／缩棋盘给侧栏／浮动推演小窗 | 设计反例：与"棋盘即主角、平面面板、克制"冲突（`ITERATION_PLAN_ROUND_NEXT.md:270`）；注意红线否决的是"浮动小窗"形态，不否决已交付的沙盘玩法能力本身。 |
| 真人目检／K5 人工试玩复活 | 用户 2026-11-23 明确取消（`AI_TIERS.md:189-190`）；K5 仍为"未测"，不作"入门档已验收"声明，也不因本轮评估复活。 |
| 棋子平衡 R1–R8（规则语义变更） | 触及走法语义 → `RULE_VERSION` 升位 + 三端 7 处触点 + 对拍重跑（`ITERATION_PLAN_ROUND_NEXT.md:166,190-195`）；调度裁定需单独立项，本轮"玩法与内容"不越界。 |

## 五、我判断的最大缺口（一句话）

**不是"没有功能"，而是"讲不出为什么"——本项目把复杂规则做进引擎、把走得好坏做成档位标签，却唯独缺了把"这条特色规则在这里怎么起作用、这手为什么好/错"讲给玩家听的那一层；它是 2025 趋势（move explanations）与本项目"让复杂规则变得可理解"主线的交叉点，也是唯一能靠纯本地静态内容补齐、零采集零联网即可兑现的高感知缺口。**
