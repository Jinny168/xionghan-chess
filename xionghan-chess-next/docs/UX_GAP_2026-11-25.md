## 1. 体验视觉完成度评估

### 1.1 先校正「12 / 2 / 3」的读法

`docs/visual_alignment_ledger.json:12-15` 的判档口径：`aligned` 极差 ≤ 0.005，`minor` ≤ 0.02，其余 `drift`，不可比 `form`。据此：

- **aligned 12 ≠ 三端体验一致**。VA-05 的 `web: null`（`visual_alignment_ledger.json:137`）就是把 web 旧树的写死 `2px` 投影单列到 VA-06 缺陷项；VA-14/15/16/17 四项 `aligned` 的能力全部默认关；VA-04 只对齐字号 1.15r，字族仍是打包 Noto Serif SC / 系统 KaiTi / 楷体回退栈（`visual_alignment_ledger.json:105`）。
- **minor 2 是「记录在案、不为它改代码」**，清单原文即写明 VA-03「肉眼不可辨；记录在案，不建议为此改代码」（`visual_alignment_ledger.json:80`）。
- **form 3 是形态项**。VA-07 的备注已经写明「三端已一致：桌面 / web 旧树 / webapp 均为格内圆角方框」（`visual_alignment_ledger.json:175`），它仍标 `form` 只因 `compare=false`；VA-01/VA-06 才是真有形态口径差，其中 VA-06 是技术债而非设计差异（`docs/VISUAL_ALIGNMENT_TRIAD.md:36`）。
- 清单是**现状快照**，不是「应该相等」的目标值；三端对齐了也要显式更新清单与 TRIAD，否则门禁会红（`docs/VISUAL_ALIGNMENT_TRIAD.md:23`）。

## 2. 对标优势分析

### 2.0 对标原文（调度方 WebSearch 实检，逐字摘录，不改数字）

> Lichess：clean minimalist interface、ad-free、棋盘与棋子主题克制、dark/light themes suited for long sessions、界面「disappears so you can focus entirely on your next move」。Chess.com：polished and visually appealing、various board themes/piece sets/customization，但免费版有 ads。（lichess.org 博客、chessprozone）
> 中国象棋 App：天天象棋「极简木纹棋盘」；博雅中国象棋「水墨风格，传统美学」；全民象棋「皮肤装扮系统、对局特效、名片、头像框」；王者象棋「3D 沉浸式、VR 模式」；天时象棋「敦煌壁画元素、每颗棋子历史典故语音、古琴 BGM」；《这不是象棋》「物理引擎、生命值与技能卡」。（今日头条、PP助手、hk1c、easck.net 2025 评测）
> 2025 趋势：个性化训练、着法解释、adaptive curricula；移动端「offline play、low data usage」被列为优先项。（chessprozone.com/blog/best-chess-apps-2025）
> 项目既有设计反例（ITERATION_PLAN_ROUND_NEXT.md §7）：绝杀粒子全屏覆盖层 / 将军旋转尖刺 / 12 种音效 + BGM —— 明确不学，全屏层打断「棋盘即主角」，与平面面板/克制气质冲突。

## 6. 与调度方判断不一致

以下为复核仓库后发现的**前提精度问题**，按调度要求单列，不并入正文结论：

- **P-1「22 枚子」不是全局口径。** `docs/GAME_MODES.md:12,19-21` 写明全子 = 11 型 25 枚/方（完整档、经典档），减子 = 9 型 22 枚/方（精简档）；`README.md:63` 写「完整档 50 子 / 每方 25」。22 枚只对应精简档，不宜作为项目整体棋子数表述。
- **P-2「三套棋子美术 + 字形模式」是桌面口径，不是三端口径。** 桌面 `src/xionghan_chess/desktop/config.py:328` 为 `("glyph","traditional","modern","cartoon")`；web 旧树 `web/index.html:146` 四个选项；Android 离线页 `android/Resources/assets/offline/index.html:31` 三项；**webapp 公网门面只有 traditional / modern 两项**（`webapp/index.html:218-221`，i18n 亦仅 `style.traditional` / `style.modern`：`webapp/js/i18n.js:312-313`）。不能以「三端各有三套+字形」为前提做视觉评估。
- **P-3「颜色非唯一载体（特色子有形状徽记）」在默认态不成立。** 徽记 `piece_badges` / `pieceBadges` 默认 false（`src/xionghan_chess/desktop/config.py:116`、`web/js/app.js:75`、`visual_alignment_ledger.json:358`）。准确表述是「已实现形状徽记，开启后颜色非唯一载体；默认仍靠字形与颜色」。
- **P-4「投影偏移 0.10r 三端收口」若理解为三端实现一致则不成立。** VA-05 的 `web: null` 与 VA-06 明确 web 旧树写死 `2px` 且不随格缩放（`visual_alignment_ledger.json:130,151`；`web/js/app.js:299`）；桌面是径向渐变、webapp 是 canvas 阴影，偏移数值对齐不等于形态对齐。
- **P-5 附带发现（非调度方前提，属仓库文档内部误差）：VA-06 note 与 TRIAD 表格写 webapp `offsetY 0.14r`，源码是 `0.10r`。** `webapp/js/ui/board.js:537` 为 `ctx.shadowOffsetY = r * 0.10`，且与 VA-05 的 aligned 值一致（`visual_alignment_ledger.json:139-141`）。C4 实施前应先更正 `visual_alignment_ledger.json:151` 与 `VISUAL_ALIGNMENT_TRIAD.md:36` 的 `0.14r`，不要按 0.14 复制。
- **P-6「桌面 reduced-motion 无系统级入口」需补半句。** 精确状态是「桌面代码未接入系统级入口，且本轮裁定不做；Qt 6.12 已暴露原生入口，缺 Windows 真机 A/B」（`ARCH_DECISIONS_2026-11-23.md:262-268,302-308`）。`docs/KNOWN_ISSUES.md:84-91` 仍留「待 Qt 暴露」旧口径，档案未同步 —— 本文不修改该文件，列为下轮更正项。
