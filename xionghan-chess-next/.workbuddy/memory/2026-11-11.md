### ⚠ 误判纠正：所谓「双进程污染」不存在（务必记住）
**我判错了。** 当时看到两个 `python.exe` 且命令行完全相同，就判定为两条并发标定链，据此把 7 局作废、停 worker、写进文档。后续验证推翻：
- `.venv/Scripts/python.exe`（274712 B）是 venv launcher，`sys._base_executable = C:\Python312\python.exe`；它拉起 base python 作**子进程**并原样传参。
- 实测 CPU 时间：父 PID 23128（venv launcher）`UserMode≈0s` / `Kernel≈0.02s`；子 PID 14924（base python）`UserMode≈364.9s`，且 `14924.ParentProcessId=23128`。内存 9MB / 46MB 亦吻合 launcher / 实算进程。
→ 「两个 python.exe + 相同命令行」是**一条链的两层**，不是并发；`timeout.exe`/`env.exe`/venv launcher/base python 是同一条命令的四层包装。**判定并发必须看 ParentProcessId、CPU 时间、`sys._base_executable`，不能只数进程名或比命令行。**
- 原 7 局（1..7 连续、dup=0、坏行 0）**无污染证据**，原理由「CPU 争抢致 K1 失真」不成立。但隔离已完成、新 checkpoint 重跑已启动，为避免两份 checkpoint 混用造成审计口径不清，维持整批作废归档为 `2026-11-11-bm-root18-final-n64.POLLUTED-dual-process.jsonl.bak`（文件名保留以免破坏引用，**含义是「因误判隔离」，不是数据污染**），不并入正式数据。代价约 7 局 / 10 分钟。
- `docs/AI_TIERS.md` §12 已整节改写为「一次误判与纠正」，§11 状态句同步修正；`Stop-Process -Force` + `TaskStop`（22m20s, cancelled）是误判下的处置，一并记录。
- 教训：进程快照里必须同时取 ParentProcessId 与 CPU 时间；`calibrate_levels.py:340` 的 `open("a")` + 每局 flush 下，「文件看起来干净（局号连续/无 dup/无坏行）」既不能证单进程也不能证双进程。
