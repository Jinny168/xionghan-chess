### 关键判断（可复用）

1. **「已修好的东西会再丢」**：1.6.0 修过限流、1.7.5 全仓 0 命中。根因不是水平，是
   **修复没转成断言**。凡只改代码不写测试的修复，寿命一个版本。
2. **空绿会转移层级**：pytest 层的静默 skip 修掉后，CI 层「注释声称有断言、实际无人消费」
   照样放行。修 P0 时要顺着「断言在哪一层执行」一路查到底。
3. **本机整跑数字自今天起不可信**：三人并发 pytest 把 442s 拖到 669s / 20min。
   判据应是 pytest 汇总行，不是 shell rc（沙箱守卫会在解释器退出阶段杀进程，
   出现过「32 条全绿但 rc=1」）。合并前用分段验证，最终由 CI 独占 runner 定案。
4. **临界 flaky 的识别**：R1 修复前连跑 5 轮 2 红 3 绿、单跑单参数 100% 红。
   「必红」与「稳定绿」都不对，真相是「预算 50ms 卡在能算完/算不完的边界」。
