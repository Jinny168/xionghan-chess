# 匈汉象棋 - 单机联机对战测试指南

## 问题分析

当您在**同一浏览器**打开两个标签页测试联机对战时，可能会遇到问题。这是因为：

### 原因1：Socket.IO连接共享
- 某些浏览器可能会共享WebSocket连接
- 两个标签页可能使用相同的Session ID
- 导致服务器无法区分两个玩家

### 原因2：缓存问题
- 浏览器缓存了旧的JS文件
- 导致代码未更新

### 原因3：disconnect事件触发
- 关闭一个标签页会触发disconnect
- 可能误删房间

## 推荐测试方案

### 方案一：使用不同的浏览器（推荐）⭐

这是最简单可靠的方式：

1. **窗口1**：使用 Chrome 浏览器
   ```
   http://localhost:5000
   ```
   
2. **窗口2**：使用 Edge 或 Firefox 浏览器
   ```
   http://localhost:5000
   ```

3. **操作步骤**：
   - 窗口1：点击"创建房间"，复制房间号（如 `ffc8c59e`）
   - 窗口2：点击"加入房间"，输入房间号，点击"加入"
   - 两个窗口应该都能看到"游戏开始"提示

### 方案二：使用Chrome的无痕模式

1. **窗口1**：正常Chrome窗口
   ```
   http://localhost:5000
   ```

2. **窗口2**：Chrome无痕窗口（Ctrl+Shift+N）
   ```
   http://localhost:5000
   ```

### 方案三：强制刷新清除缓存

如果必须使用同一浏览器的两个普通标签页：

1. **打开两个标签页**
2. **在每个标签页按 Ctrl+Shift+R**（强制刷新，清除缓存）
3. **等待3秒**让Socket.IO连接稳定
4. **窗口1**：创建房间
5. **窗口2**：加入房间

## 调试步骤

### 1. 检查服务器日志

启动服务器时应该看到：

```
==================================================
Xionghan Chess Web Server Started
URL: http://localhost:5000
Async Mode: threading
Room Timeout: 3600s
IP Rate Limit: 5 connections
Static Cache: 31536000s
==================================================
```

### 2. 检查浏览器控制台

**窗口1（房主）**应该看到：
```
✅ Socket.IO连接成功, ID: xxxxxxxx
🚀 正在连接房间: ffc8c59e
✅ 成功加入房间，阵营: red
👤 玩家信息: 红方（房主）, 对手状态: 等待中
 等待对手连接...
```

**窗口2（客人）**应该看到：
```
✅ Socket.IO连接成功, ID: yyyyyyyy
🚀 正在连接房间: ffc8c59e
✅ 成功加入房间，阵营: black
👤 玩家信息: 黑方（客人）, 对手状态: 已连接
🎮 游戏开始！
```

**服务器控制台**应该看到：
```
客户端连接: xxxxxxxx (IP: 127.0.0.1)
客户端连接: yyyyyyyy (IP: 127.0.0.1)
 游戏开始: 房间 ffc8c59e, 模式: xionghan
```

### 3. 测试走子同步

1. **窗口1（红方）**：移动一个棋子
2. **窗口2（黑方）**：应该立即看到棋子移动
3. **窗口2（黑方）**：移动一个棋子
4. **窗口1（红方）**：应该立即看到棋子移动

如果看到"不是你的回合"错误，说明回合同步正常工作。

### 4. 常见问题排查

#### 问题：显示"房间不存在"
- **原因**：房间号大小写问题或房间已超时
- **解决**：确保输入的房间号完全一致（已修复大小写不敏感）

#### 问题：两个窗口都是红方
- **原因**：Socket.IO连接未正确区分
- **解决**：使用不同浏览器或无痕模式

#### 问题：走子不同步
- **原因**：网络事件未正确触发
- **解决**：检查浏览器控制台的"📥 收到对手移动"日志

#### 问题：关闭窗口后房间消失
- **原因**：disconnect事件触发了房间清理
- **解决**：正常现象，重新创建房间即可

## 代码优化说明

已优化的内容：

1. ✅ **房主标识**：加入房间时返回`isHost`字段
2. ✅ **回合验证**：服务端验证是否是该玩家的回合
3. ✅ **大小写不敏感**：房间号查询忽略大小写
4. ✅ **玩家信息**：回合指示器显示"你的回合/对手回合"
5. ✅ **disconnect优化**：正确处理玩家断开连接
6. ✅ **调试日志**：增强服务器和客户端的日志输出
